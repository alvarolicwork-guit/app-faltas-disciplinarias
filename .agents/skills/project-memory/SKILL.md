# Continuidad del proyecto

Localizar la raíz Git app-faltas y el workspace padre. Leer primero [base vigente](../../../docs/BASE_CONOCIMIENTO_APP.md); para decisiones operativas consultar ../../../../.ai/session.md, memory.md, decisions.md y context.md solo en las secciones relevantes. La auditoría reside en ../../../docs/auditoria-2026-10-26/INFORME.md.

Mantener separados: instrucciones recientes del usuario, política histórica, comportamiento de código y evidencia de producción. Fechas, commits, padrones y cuentas anotados en .ai pueden estar desactualizados: verificar lo necesario en el módulo real. La app está operativa; una prueba no ejecutada en esta sesión no significa servicio no conectado.

Conservar decisiones, razones, archivos afectados y pruebas con fecha y alcance. No marcar Hxx resuelto por un build ni sobrescribir el informe histórico. Una propuesta sigue pendiente hasta que se acuerde; la configuración de skills no modifica permisos de negocio.

Actualizar documentación local cuando la tarea autorizada lo requiera, con notas breves y sin transcripciones, credenciales, tokens ni datos personales. Para la memoria global de Codex respetar su política específica y la autorización del usuario; esta skill no concede permiso general de escritura allí.

No duplicar los documentos canónicos ni importar contexto de otras apps. Si falta contexto, explicitar la laguna y continuar con lo verificable. La finalización informa archivos guardados y limitaciones; no implica commit, respaldo remoto ni despliegue.
